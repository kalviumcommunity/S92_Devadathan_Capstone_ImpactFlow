# ImpactFlow client

The client is a React application built with Vite. It includes a responsive
workspace dashboard and sign-in with either an ImpactFlow username/password or
Google OAuth.

## Run locally

Start the API and leave it running in one terminal:

```sh
cd server
npm install
npm start
```

In a second terminal, start the client:

```sh
cd client
npm install
npm run dev
```

The client expects the API at `http://localhost:5000` by default. To use a
different API origin, set `VITE_API_URL` in the client's `.env` file.
Google sign-in and email sign-in both require the API to be running.

## Deploy on Render

The repository includes a Render Blueprint (`render.yaml`) for the Node API and
React static site. In Render, choose **New → Blueprint**, connect this GitHub
repository, and deploy the blueprint. Set the prompted secret and URL values
in Render, not in source control:

- `MONGO_URI`: a MongoDB connection string.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: OAuth credentials from your
  Google Cloud project.
- `GOOGLE_CALLBACK_URL`: `https://<api-service>.onrender.com/auth/google/callback`.
- `CLIENT_URL`: `https://<static-site>.onrender.com`.
- `VITE_API_URL`: `https://<api-service>.onrender.com`.

Add the deployed callback URL to the authorised redirect URIs in the Google
OAuth client. After changing `VITE_API_URL`, redeploy the static site because
Vite embeds it at build time. `JWT_SECRET` is generated by Render.

Both services use Render's free tier. Free web services can sleep when idle,
and their local filesystem is temporary: uploaded files may be lost when the
API restarts or redeploys. Use durable external file storage before relying on
uploads for NGO records.

## Deploy the frontend on Netlify

The repository root includes a `netlify.toml` configured to build the client
from the `client` directory, publish `client/dist`, and route client-side
navigation to the app entry point. It also sets `VITE_API_URL` to the
production Render API.

To enable continuous deployment, import this GitHub repository in Netlify and
deploy with the detected settings. If you change the API URL, update
`VITE_API_URL` in Netlify's environment variables or `netlify.toml`, then
trigger a new deploy. Keep OAuth client secrets and other credentials in the
hosting provider's environment settings, never in the frontend or repository.

## Run with Docker

From the repository root, start the full application (React frontend, API, and
MongoDB) with:

```sh
docker compose up --build
```

Open `http://localhost:8080`. The frontend container serves the built app and
proxies `/api` and `/auth` requests to the API container. MongoDB data and
uploaded files are kept in named Docker volumes. To stop the services, run
`docker compose down`; add `-v` only if you intend to delete those volumes.

The Compose setup uses local-only defaults for `JWT_SECRET` and does not
configure Google OAuth. Before using it beyond local development, set a strong
`JWT_SECRET` and the Google OAuth variables (`GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `GOOGLE_CALLBACK_URL`, and `CLIENT_URL`) in a local
`.env` file. Do not commit `.env` or use the local defaults in production.

## Workspace pages

Programs, reports, and organisation settings have interactive layouts with
sample records so the screens can be explored immediately. Program entries
and settings are currently stored in the browser only; they are not shared
between users or devices and should not be treated as an NGO's official
records. The included sample metrics are illustrative, not live impact data.
Server-backed program and organisation settings APIs are needed before
multi-user or production use.

## Profile, appearance, and documents

Use the Help button for workspace navigation and the signed-in name/avatar to
open the personal profile. The sun/moon switch beside Help changes light and
dark appearance. The theme preference and profile details are stored in the
current browser; they are not synced to an NGO account.

The beneficiary screen currently contains a sample record rather than a
complete live registry. Documents can be uploaded to the connected API in PDF,
image, Word, Excel, or CSV format, up to 10 MB per file. The client does not
currently display uploaded-document history, retention status, or access
permissions. Follow the organisation's consent, access, and retention policies
before uploading sensitive information.

## Authentication setup

Start the API and configure its environment before using either sign-in
method. Google OAuth requires `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `GOOGLE_CALLBACK_URL`, `JWT_SECRET`,
`MONGO_URI`, and `CLIENT_URL`.

For local development, set `GOOGLE_CALLBACK_URL` to
`http://localhost:5000/auth/google/callback` and `CLIENT_URL` to
`http://localhost:5173`. The callback URL must also be registered in the
Google OAuth client configuration.
